# HAUSDAME GUEST EXPERIENCE

# GUEST GUIDE VISUAL SYSTEM

Definición oficial del sistema visual, principios UX y lineamientos de diseño para la Guía del huésped de Hausdame Guest Experience.

Este documento funciona como referencia para diseño, producto y agentes de desarrollo.

---

# 1. Propósito

Guest Experience no debe sentirse como software empresarial.

Debe sentirse como:

* una app de estancia;
* una guía personalizada;
* una experiencia móvil de hospitalidad;
* una herramienta simple y clara para el huésped.

El objetivo principal es que el huésped:

* entienda todo inmediatamente;
* encuentre información rápido;
* reduzca estrés;
* tenga una experiencia agradable;
* no necesite aprender a usar la interfaz.

La Guía del huésped debe sentirse como:

> la app personalizada de la estancia.

No como:

> un software de administración.

---

# 2. Filosofía principal

## Simple feels premium

La experiencia debe sentirse:

* simple;
* ligera;
* clara;
* rápida;
* humana;
* relajada;
* organizada.

En hospitalidad, menos fricción suele sentirse más premium.

La simplicidad no es una limitación del MVP. Es una decisión de producto.

La Guía del huésped no debe competir por atención. Debe resolver.

---

# 3. App feeling

La experiencia correcta no es “abrir una página web”.

La experiencia correcta es:

> entrar a la app de tu estancia.

Guest Experience debe sentirse más como:

* una travel app;
* una concierge app;
* una app hotelera;
* una guía vacacional;
* una experiencia móvil personal.

Y menos como:

* un PMS;
* un CRM;
* un dashboard;
* un ERP;
* un panel administrativo.

---

# 4. UX pillars

## 4.1 Mobile First

La experiencia está diseñada principalmente para móvil.

El huésped probablemente accederá:

* desde WhatsApp;
* caminando;
* cansado;
* llegando al alojamiento;
* con mala señal;
* desde un dispositivo vertical;
* con poco tiempo para leer.

Todo debe priorizar:

* navegación vertical;
* lectura rápida;
* targets táctiles grandes;
* scroll natural;
* rendimiento rápido;
* claridad inmediata.

Desktop puede existir, pero no debe dirigir las decisiones visuales principales.

---

## 4.2 Hospitality UI

La interfaz debe transmitir:

* calma;
* claridad;
* confianza;
* acompañamiento;
* organización;
* cuidado.

La app no debe sentirse fría, técnica o administrativa.

Debe sentirse como una extensión digital del buen anfitrión.

---

## 4.3 Scanability

El huésped debe entender la pantalla en segundos.

El contenido debe ser:

* escaneable;
* visual;
* jerárquico;
* resumido;
* fácil de ubicar.

Evitar:

* bloques largos de texto;
* párrafos enormes;
* instrucciones complejas;
* información escondida;
* densidad visual excesiva.

---

## 4.4 Zero Friction

La navegación debe ser extremadamente simple.

El huésped no debe:

* aprender navegación compleja;
* abrir múltiples menús;
* buscar información escondida;
* interpretar interfaces técnicas;
* pasar por pasos innecesarios.

Cada pantalla debe tener una intención clara.

---

## 4.5 Large Touch Targets

Todos los elementos interactivos deben ser cómodos para touch.

Priorizar:

* cards grandes;
* botones amplios;
* spacing generoso;
* targets táctiles cómodos;
* navegación con el pulgar.

Evitar elementos pequeños o difíciles de tocar.

---

## 4.6 Content First

El contenido es más importante que los controles.

La prioridad es:

1. información útil;
2. claridad visual;
3. rapidez de acceso;
4. sensación de acompañamiento.

No priorizar:

* configuraciones;
* controles avanzados;
* herramientas administrativas;
* personalización excesiva.

---

## 4.7 Calm Visual Hierarchy

La interfaz debe sentirse tranquila.

Debe haber jerarquía clara entre:

* título;
* subtítulo;
* información principal;
* acciones;
* detalles secundarios.

Evitar pantallas que compitan por atención con demasiados elementos al mismo tiempo.

---

## 4.8 Universal Navigation

La navegación debe ser obvia.

El huésped debe reconocer fácilmente:

* dónde está;
* qué puede tocar;
* cómo volver;
* qué información está viendo;
* cuál es la acción principal.

---

# 5. Sistema de navegación

La navegación debe sentirse natural.

## Reglas

* scroll vertical natural;
* navegación simple;
* pocas capas;
* secciones claras;
* cards reconocibles;
* accesos rápidos.

Evitar:

* sidebars complejos;
* nested navigation;
* multipanel;
* menús ocultos excesivos;
* navegación tipo dashboard.

Las referencias visuales oficiales muestran una experiencia basada en:

* cards;
* secciones;
* listas visuales;
* accesos rápidos;
* pantallas enfocadas.

---

# 6. Sistema de cards

Guest Experience es una plataforma basada principalmente en cards.

Las cards deben ser:

* grandes;
* respirables;
* táctiles;
* claras;
* fáciles de escanear;
* visualmente consistentes.

Las cards no deben ser:

* miniatura;
* densas;
* saturadas;
* llenas de texto;
* visualmente ambiguas.

## Buenas cards

Una buena card debe responder rápido:

* qué es;
* para qué sirve;
* qué debo hacer;
* si puedo tocarla.

## Densidad

Cada card debe contener solo lo necesario para tomar una decisión o entender una información.

Si una card necesita demasiado texto, probablemente debe dividirse en otra sección o bloque.

---

# 7. Sistema de iconografía

## Regla principal

Usar iconografía universal.

El huésped debe reconocer inmediatamente cada sección.

## Ejemplos

| Función      | Icono sugerido   |
| ------------ | ---------------- |
| Wi-Fi        | señal Wi-Fi      |
| Check-in     | puerta / llave   |
| Transporte   | automóvil / bus  |
| Restaurantes | cubiertos        |
| Compras      | bolsa            |
| Emergencias  | cruz / alerta    |
| Contacto     | teléfono         |
| Ubicación    | pin              |
| Normas       | documento / casa |
| Check-out    | salida / maleta  |

## Restricciones

No usar:

* iconos artísticos;
* iconos ambiguos;
* múltiples estilos mezclados;
* iconografía decorativa sin función;
* iconos difíciles de interpretar.

Mantener:

* consistencia;
* simplicidad;
* reconocimiento inmediato;
* estilo visual único.

---

# 8. Uso de imágenes

Las imágenes deben ayudar al huésped.

No deben ser solamente decorativas.

## Priorizar fotos útiles

* entrada;
* acceso;
* estacionamiento;
* lockbox;
* puerta;
* edificio;
* elevador;
* ubicación;
* referencias visuales para llegar;
* instrucciones que se entienden mejor con imagen.

## Evitar

* exceso de fotografías;
* galerías enormes;
* imágenes irrelevantes;
* imágenes redundantes;
* fotos bonitas pero inútiles;
* fotos que aumentan ruido visual.

## Regla

Una imagen debe reducir confusión.

Si no ayuda a entender, llegar, entrar, usar o resolver algo, probablemente no debe estar ahí.

---

# 9. Reglas de contenido

El contenido debe ser:

* corto;
* humano;
* claro;
* visual;
* fácil de traducir;
* orientado al huésped.

Evitar:

* lenguaje técnico;
* instrucciones excesivas;
* párrafos largos;
* texto administrativo;
* tono legalista innecesario.

## Principio

El huésped debe entender todo rápidamente.

Pensar siempre en un huésped:

* cansado;
* llegando tarde;
* con equipaje;
* con poca batería;
* con mala señal;
* sin contexto local.

---

# 10. Idioma y tono

El tono debe ser:

* amable;
* directo;
* útil;
* natural;
* calmado.

Evitar tono:

* corporativo;
* robótico;
* excesivamente formal;
* técnico;
* agresivo.

## Ejemplo correcto

“Conéctate a esta red Wi-Fi.”

## Ejemplo incorrecto

“El usuario deberá seleccionar la red inalámbrica correspondiente al inmueble.”

---

# 11. Estructura visual de secciones

Cada sección debe tener una intención clara.

Ejemplos:

* Wi-Fi: acceso rápido.
* Check-in: entrar sin fricción.
* Ubicación: llegar correctamente.
* Normas: prevenir problemas.
* Transporte: moverse fácilmente.
* Restaurantes: descubrir opciones.
* Actividades: mejorar la estancia.
* Emergencias: resolver rápido.
* Contacto: pedir ayuda.
* Check-out: salir correctamente.

Cada sección debe responder:

1. ¿Qué necesita saber el huésped?
2. ¿Qué acción puede tomar?
3. ¿Qué información debe ser visible primero?
4. ¿Qué puede quedar como detalle secundario?

---

# 12. Anti-patterns

Guest Experience no debe usar:

* tablas;
* dashboards;
* sidebars enterprise;
* layouts tipo CRM;
* formularios largos;
* modales gigantes;
* settings complejos;
* navegación técnica;
* cards pequeñas;
* listas densas;
* exceso de texto;
* jerarquías complejas;
* pantallas multipanel;
* experiencia tipo administración;
* lenguaje de sistema;
* copywriting frío.

Si una pantalla empieza a parecer software administrativo, debe rediseñarse.

---

---

# 14. Dirección del MVP

El MVP debe priorizar:

* simplicidad;
* claridad;
* rapidez;
* app feeling;
* navegación natural;
* experiencia móvil;
* utilidad inmediata;
* hospitalidad digital.

No priorizar todavía:

* IA;
* automatizaciones complejas;
* configuraciones avanzadas;
* themes sofisticados;
* builders avanzados;
* marketplace;
* smart locks;
* reglas complejas.

El MVP debe demostrar que una guía simple, clara y bien diseñada ya puede sentirse premium.

---

# 15. Relación con el Host

Aunque el Host configura la guía, la experiencia visual principal debe diseñarse para el huésped.

El Host debe sentir que está configurando algo simple.

El huésped debe sentir que está usando algo cuidado.

No construir el editor Host con una lógica visual que contamine la experiencia huésped.

---

# 16. Reglas para agentes de desarrollo

Antes de implementar una pantalla de Guest Experience, el agente debe revisar:

```txt
images/IMAGENES_AUDITADAS.md
docs/design/GUEST_GUIDE_VISUAL_SYSTEM.md
```

El agente no debe improvisar una UX tipo dashboard.

El agente no debe introducir:

* tablas;
* layouts enterprise;
* formularios densos;
* navegación administrativa;
* componentes visuales inconsistentes.

Si una implementación requiere desviarse de este sistema visual, el agente debe reportarlo antes de editar.

---

# 17. Regla final

Guest Experience debe sentirse como:

> la app personalizada de la estancia.

No como:

> un software de administración.

La experiencia debe ser simple, móvil, clara, humana y útil.
